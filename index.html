Циклы: for и while

Цикл повторяет кусок кода столько раз, сколько нужно. Не надо писать одно и то же вручную.

Зачем нужен цикл

Допустим, надо пять раз вывести слово «привет». Можно написать print пять раз подряд. А если сто раз? Или тысячу? Писать это руками долго и скучно. Цикл сделает это за тебя:

for i in range(5):
    print("привет")

Читается так: «для каждого i из пяти чисел напечатай привет». Переменная i по очереди становится 0, 1, 2, 3, 4. Значений пять, значит, и повторов пять.

Перед print стоит отступ из четырёх пробелов. Всё, что с отступом под for, входит в цикл. Если отступ забыть, Python покажет ошибку.

for и range

range(start, stop, step) выдаёт числа. start — с какого числа начать. stop — на каком остановиться, но само это число не берётся. step — на сколько прибавлять каждый раз. Если start и step не писать, start будет 0, а step будет 1.

Подвигай ползунки и нажми «Запустить». Лягушка прыгает по тем числам, которые выдал range.

Функции

  
Функция — это кусочек программы с именем, который можно вызывать сколько угодно раз. Соковыжималка, чёрный ящик и конструктор кода ждут.

Что такое функция

  
Представь блендер. Кладёшь банан, нажимаешь кнопку — получаешь смузи. Кладёшь яблоко — получаешь яблочный сок. Блендеру всё равно, что внутрь положили: он знает свою работу и отдаёт результат.

  
Функция в Python — такой же «блендер» внутри программы. Ты даёшь ей данные, она что-то делает и возвращает результат. А главное — один раз написал, сколько угодно раз вызвал. Код не нужно переписывать.

  
def make_juice(fruit, count):      # def = «создать функцию»
    print(f"Выжимаю {fruit}...")   # тело функции — всё с отступом
    return count                   # return отдаёт результат наружу

cups = make_juice("яблоко", 3)     # вызов: вместо параметров встали значения
print(f"Получилось {cups} стакана сока!")

  
    
    
  • def — слово, которое говорит Пайтону: «сейчас будет функция».
    • 
    
  • make_juice — имя. По нему функцию вызывают: make_juice(...).
    • 
    
  • fruit, count — параметры. Пустые места, куда при вызове встанут значения.
    • 
    
  • return — отдаёт результат тому, кто вызвал функцию.
    •

print и return — не одно и то же

  
Самая частая путаница новичка. print просто показывает текст на экране. return отдаёт значение обратно в программу — его можно сохранить в переменную и использовать дальше.

  
Кассир может сказать вслух «спасибо за покупку» — это print. А реально протянуть тебе чек — это return.

  
def say_hi():
    print("привет")     # просто крикнули на весь экран

def give_hi():
    return "привет"     # реально протянули значение

x = say_hi()    # на экране «привет», но внутри x — None
y = give_hi()   # на экране ничего, зато внутри y — «привет»

Big O: учим алгоритмы

  
План урока: сначала разберёмся, что такое Big O, потом посмотрим, как работают поиск и сортировка, а в конце ты напишешь алгоритм сам.


  
Что такое Big O

  
Представь, что нужно найти слово в словаре. Можно листать с первой страницы, а можно открыть словарь посередине и сразу понять, в какой он половине. Оба способа найдут слово, но второй сделает гораздо меньше шагов.

  
Big O (читается «О большое») показывает, как быстро растёт число шагов алгоритма, когда растёт размер данных. Размер данных обозначают буквой n: это число домиков, элементов массива или слов в словаре.

  
Есть три важных договорённости:

  
    
    
  • Мы считаем шаги, а не секунды. Секунды зависят от компьютера, шаги — нет.
    • 
    
  • Мы смотрим на худший случай: клад оказался в самом последнем домике.
    • 
    
  • Мелочи отбрасываем. Если алгоритм делает 3n шагов, мы всё равно пишем O(n), потому что важна форма роста, а не множитель.
    • 
  

  

    
ЗаписьНазваниеПримерШагов при n = 1000

    
      
O(1)константнаявзять элемент массива по номеру1

      
O(log n)логарифмическаябинарный поискоколо 10

      
O(n)линейнаяодин цикл по всем элементам1000

      
O(n log n)линеарифмическаясортировка слияниемоколо 10 000

      
O(n²)квадратичнаяцикл в цикле, пузырьковая сортировка1 000 000

    
  

  
Как оценить сложность по коду

  
    
    
  • Просто обратились к элементу по номеру: O(1).
    • 
    
  • Один цикл от 1 до n: O(n).
    • 
    
  • Цикл внутри цикла, оба до n: O(n²).
    • 
    
  • На каждом шаге отбрасываем половину данных: O(log n).
    •

Часть 2. Сортировка: расставь по порядку

  
Сортировка — это расстановка элементов по порядку, например от меньшего к большему. Она нужна, чтобы работал бинарный поиск: он умеет искать только в упорядоченных данных. Способов сортировки много, мы разберём два.

  
Пузырьковая сортировка

  
Идём по массиву и сравниваем двух соседей. Если левый больше правого, меняем их местами. После первого прохода самый большой элемент оказывается в конце, как всплывший пузырёк. Повторяем проходы, пока всё не встанет по порядку.

  
[4, 2, 5, 1]   сравниваем 4 и 2, меняем   -> [2, 4, 5, 1]
[2, 4, 5, 1]   сравниваем 4 и 5, не меняем
[2, 4, 5, 1]   сравниваем 5 и 1, меняем   -> [2, 4, 1, 5]
пятёрка встала на место, начинаем новый проход

  
Нужно примерно n проходов, и в каждом около n сравнений. Поэтому сложность O(n²).

  
Сортировка слиянием

  
Две уже отсортированные кучки легко слить в одну: смотрим на первые элементы кучек и каждый раз берём меньший.

  
[2, 4] и [1, 5]:  берём 1, потом 2, потом 4, потом 5  -> [1, 2, 4, 5]

  
Но откуда взять отсортированные кучки? Делим массив пополам и сортируем каждую половину тем же способом. Так делим, пока в куче не останется один элемент, а один элемент уже отсортирован. Деление пополам даёт log n уровней, а на каждом уровне слияние проходит по всем n элементам. Итого O(n log n).

  
Для 24 столбиков разница небольшая. Но для 1000 элементов пузырёк сделает около миллиона сравнений, а слияние — около десяти тысяч.

Четыре способа расставить числа по порядку, и чем они отличаются.


  
Зачем сортировать

  
Сортировка — это расстановка элементов по порядку: от меньшего к большему или наоборот. Книги на полке, фамилии в журнале, цены в магазине. Там, где всё стоит по порядку, искать проще. Бинарный поиск из прошлого урока тоже работает только на отсортированных данных.

  
Способов сортировки много. Они отличаются скоростью, расходом памяти и тем, насколько просто их написать. В C++ уже есть готовая функция std::sort, но полезно понимать, что происходит внутри. Мы разберём четыре способа: пузырьком, выбором, вставками и быструю.

  
Все они сортируют по возрастанию и работают «на месте»: не заводят второй массив, а переставляют элементы в том же.


  
1. Пузырьковая сортировка

  
Аналогия. В стакане с газировкой лёгкие пузырьки поднимаются вверх. Здесь самые большие числа «всплывают» в конец массива.

  
    
    
  1. Сравни два соседних элемента.
    2. 
    
  2. Если левый больше правого, поменяй их местами.
    3. 
    
  3. Дойди до конца. Самое большое число теперь стоит последним.
    4. 
    
  4. Повтори всё для оставшихся элементов. Последний уже на месте, его не трогаем.
    5. 
  

  
Время: O(n²). Память: O(1). Устойчивая: да. Плюс: очень простая. Минус: медленная, делает много лишних сравнений.


  
2. Сортировка выбором

  
Аналогия. Учитель строит класс по росту. Находит самого низкого и ставит на первое место. Потом находит самого низкого из оставшихся и ставит на второе. И так до конца.

  
    
    
  1. Найди самый маленький элемент среди тех, что ещё не расставлены.
    2. 
    
  2. Поменяй его местами с первым из нерасставленных.
    3. 
    
  3. Граница между готовой и неготовой частью сдвигается на один вправо.
    4. 
    
  4. Повторяй, пока не дойдёшь до конца.
    5. 
  

  
Время: O(n²) всегда, даже если массив уже отсортирован. Память: O(1). Устойчивая: нет. Плюс: делает мало обменов, не больше n − 1. Минус: сравнений всегда много.


  
3. Сортировка вставками

  
Аналогия. Карты в руке. Берёшь новую карту и вставляешь её на нужное место среди тех, что уже лежат по порядку. Остальные карты чуть раздвигаются.

  
    
    
  1. Слева лежит отсортированная часть. Сначала это один элемент.
    2. 
    
  2. Возьми следующий элемент и запомни его в переменной key.
    3. 
    
  3. Сдвигай элементы слева на одно место вправо, пока они больше key.
    4. 
    
  4. Поставь key в освободившееся место.
    5. 
  

  
Время: O(n²) в среднем и худшем случае, но O(n), если массив почти отсортирован. Память: O(1). Устойчивая: да. Плюс: быстро работает на маленьких и почти готовых массивах. Минус: на больших случайных медленная.


  
4. Быстрая сортировка

  
Аналогия. На физкультуре выбирают одного ученика, он будет опорным. Все, кто ниже его, встают слева, кто выше — справа. Опорный уже стоит на своём месте. Потом левую и правую группу делят точно так же, и так далее, пока группы не станут по одному человеку.

  
    
    
  1. Выбери опорный элемент (у нас последний).
    2. 
    
  2. Разложи остальные: меньшие влево, большие вправо.
    3. 
    
  3. Поставь опорный между ними. Он на месте навсегда.
    4. 
    
  4. Сделай то же самое для левой и правой части. Это рекурсия: функция вызывает сама себя.
    5. 
  

  
Время: O(n log n) в среднем, O(n²) в худшем случае (если опорный всё время самый маленький или самый большой). Память: O(log n) на рекурсию. Устойчивая: нет. Плюс: на практике одна из самых быстрых. Минус: плохой случай.
